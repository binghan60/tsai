# 設計語言

介面的**設計語言文件**：原則、數值、元件用法、頁面模板，以及為什麼這樣定。改畫面前先讀，改完同一次更新這裡。

## 0. 以誰為準

| 層級 | 放在哪裡 | 地位 |
|---|---|---|
| 數值（顏色、字級、圓角、陰影） | `client/src/style.css`（`:root`／`.dark`／`@theme`／`@utility`） | **唯一來源**。`npm run build` 先跑 `scripts/audit-colors.mjs`：頁面裡寫色碼、Tailwind 固定色階（`red-500`、`slate-100`…）或原生 `title` 直接失敗 |
| 元件與頁面實作 | `client/src/components/`、`client/src/pages/` | 畫面真正長什麼樣以程式為準 |
| 設計語言（本文件） | `docs/STYLE_GUIDE.md` | 規則與理由；跟程式不一致時是本文件過時，要更新 |
| 摘要 | `CLAUDE.md` 第七節 | 每個 session 自動載入，只放最容易做錯的幾條 |

設計提案（claude.ai 上的設計稿）只是當時的提案，定案以程式與本文件為準，不要照舊設計稿把畫面改回去。

## 1. 兩套主題，同一套形狀

| | 淺色：清爽臨床 | 深色：深色專業 |
|---|---|---|
| 頁面底 `background` | `#f4f6f8` | `#07090c` |
| 卡片 `card` | `#ffffff` | `#0e1217`，頂端一條內側高光（`shadow-card`） |
| 下凹 `sunken` | `#f1f4f6` | `#0a0d11` |
| 滑過 `hover` | `#eef2f4` | `#141a21` |
| 邊框 `border`／`border-strong` | `#e2e8ec`／`#cbd4da` | `#1c232c`／`#2a3440` |
| 文字 三階 | `#0e1a21`／`#4b5a64`／`#5f6c76` | `#e8edf3`／`#8f9bab`／`#7d8999` |
| 主色 `primary` | `#007a7e`（白字） | `#37d2f2`（深字） |
| 主色淡面 `accent` | `#e2f2f2`／字 `#00595c` | `#0a2630`／字 `#7fe3f7` |

- **不用光暈**（主要按鈕、號碼牌、日曆選中日都沒有）：深色的青色光暈看了不舒服，層級靠實色底就分得出來。
- 主題切換存 `localStorage`、預設跟隨系統（`composables/useTheme.js`；`index.html` 的內嵌腳本開機時先定好 class，不會閃）。

### 表面的用法

- `bg-background` 頁面底；`bg-card` 卡片、面板、對話框；`bg-popover` 選單與浮層。
- `bg-sunken` 下凹：分段切換的軌道、次要按鈕、唯讀的內容區塊、表頭。
- `bg-hover` 滑過；`bg-field` 可以輸入的表面（淺色是白、深色往下凹一階）。
- 不要寫 `bg-white`：深色主題下就是白底配白字。

### 文字三階

`text-foreground` 主要內容；`text-muted-foreground` 次要文字、表單標籤；`text-subtle-foreground` 小標題、時間戳記、單位。可點的文字用 `text-primary`，靜止時就要看得出來，不要只在 hover 才變色。

## 2. 狀態色

| token | 淺色 前景／底 | 深色 前景／底 | 用途 |
|---|---|---|---|
| `danger` | `#880d0d`／`#ffede9` | `#ffbeb3`／`#41211d` | 失敗、刪除、遲到、藥物過敏、檢驗偏高偏低 |
| `warning` | `#874c00`／`#fff0e0` | `#f8b05d`／`#3c260d` | 待你動手、請轉告飼主、備註提醒、保證金 |
| `success` | `#2d7f3f`／`#e8f9e9` | `#4eab60`／`#19321d` | 已寄出、已完成、其餘正常 |
| `info` | `#4260c4`／`#ebf3ff` | `#82a1f6`／`#212a44` | 寄送中、草稿、初診、待審初診表、引用本次看診、待辦的期限 |
| `surgery` | `#7238a5`／`#f8efff` | `#d3adff`／`#31253f` | **只給手術標記** |
| `badge` | `#c62828`／白字 | `#ff8a80`／深字 | 工具欄的紅色數字徽章 |

- 使用端寫 `bg-warning-surface text-warning`；徽章用 `<Badge variant="status" :class="…">`，顏色由 `lib/recordStatus.js` 那類 meta 提供。
- **明度是刻意錯開的**：紅綠色盲下只剩明度可辨。淺色 danger 最深、深色 danger 最亮——危險永遠是對比最高的那一個。不要「順手對齊」。
- 新增狀態色要跟主色留 40° 以上的色相距離。
- 顏色不能是唯一線索：徽章一律帶文字（或滑過提示＋`aria-label`）；牙齒圖的狀況另有形狀記號。
- **狀態盡量有顏色，灰色只留給「已經不作用」**（已取消、已停用）。還在進行的狀態（草稿）與一般日期（待辦「明天」「10/5」）不用灰——灰色看起來像沒有狀態。看診工作區的貓咪標籤：無藥物過敏／已注射疫苗／有健檢是 success、未注射／未健檢是 warning，狀態不明不出標籤。

## 3. 字

- 中文 `Noto Sans TC Variable`、數字 `IBM Plex Mono`，都自架（`main.js` 匯入）。不要改成 CDN：報告頁是 Puppeteer 產 PDF 的來源。
- 數字（號碼牌、時間、體重、檢驗值、電話）加 `num`：等寬＋tabular-nums，上下才對得齊。

| class | 尺寸 | 用途 |
|---|---|---|
| `text-xl` | 28 | 頁面標題（每頁一個 H1） |
| `text-lg` | 22 | 區塊標題、對話框與面板標題、卡片標題 |
| `text-base` | 18 | 內文、輸入框（body 預設） |
| `text-sm` | 16 | 按鈕、表單標籤、次要文字 |
| `text-xs` | 15 | 註記、徽章、時間戳記 |
| `text-2xs` | 14 | 規格欄小標題（`spec-label`），最小字級 |
| `text-display` | 36 | 總覽數字格的大數字（配 `num`），只給「一眼看數字」的讀數，不當標題 |

尺寸與行高都在 `@theme`，改字級改那裡。不要寫 `text-[13px]` 這種任意值。報告紙面走自己的尺度，見第 8 節。

## 4. 形狀與尺寸

- 圓角：格子與小標記 6（`rounded-md`）、控制項 8（`rounded-lg`）、卡片與面板內區塊 12（`rounded-xl`）、對話框 16（`rounded-2xl`）、膠囊 `rounded-full`。
- 控制項高度 36／40／44／48，預設 40。按鈕 `size`：`xs`／`sm` 36、`default` 40、`lg` 48；圖示按鈕 `icon-xs` 32、`icon-sm` 36、`icon` 40、`icon-lg` 44。
- **同一排的按鈕與控制項一律同高**：頁首動作列、對話框與工作區的底部操作列、掛號台卡片的動作都是 40（旁邊的 `RowActions` 傳 `size="default"`、日期前後鈕用 `icon`）；清單列是 36。主要動作靠實色突顯，**不靠放大**——放大只會讓那一排對不齊。包在輸入框裡的小按鈕（`FilterBar` 的搜尋／清除）不算同一排。
- 清單列：表頭 44、資料列 64（`.desktop-data-header`／`.desktop-data-row`，欄寬由 `--data-columns` 決定）。
- 目標螢幕 1920×1080；手機寬度仍要能用（導覽換成漢堡選單、面板滿版）。

## 5. 版面

### 骨架

`左側導覽 72px ｜ 工作區 ｜（側滑面板 460px）｜ 右側工具欄 64px`（`App.vue`＋`components/shell/`）。面板一次開一個、不加遮罩、不鎖背景；1600px 以上是版面裡的一欄、把工作區往左推，更窄時浮在工作區上面。細節見 CLAUDE.md 第七節。

左側導覽分三組（看診、資料、設定），組標題是下凹底小膠囊、每組前面一條分隔線——跟項目同字級的淡色字看起來像少了圖示的項目。

### 容器只有一種

寬度與外距只在 `App.vue` 的 `<main>` 決定：**滿版**（填滿兩條欄之間、不設 `max-w`），頁面自己不包外框，沒有例外。每頁根節點 `flex flex-col gap-5`，第一個子元素是 `PageHeader`（標題、選配的筆數＋單位、說明、`back-to` 返回鈕、右邊 `actions`）。

- **表單頁也滿版，寬的時候分欄**：不讓單一輸入框拉成一整條的方法是分欄，不是限寬（限寬在 1920 螢幕上只佔左半邊、右邊空一大片）。新增貓咪的表單在內容區 ≥ 90rem（`@[90rem]/content`）時排成左右兩欄（左：飼主＋貓咪基本資料，右：生活狀況＋醫療病史，中間一條直線），不夠寬就上下排；預填模板編輯頁的欄位由 `FormSection` 依寬度分欄，跟健檢報告填寫頁同一套。
- **一張表單只用一組欄**：每一區都是 `grid gap-4 @xl:grid-cols-2 @4xl:grid-cols-3`，長欄位用 `col-span` 跨欄、整列的用 `col-span-full`，各區欄位的左右緣才對得齊。欄數看表單容器自己的寬度（`@container`），不看視窗。控制項一律預設高度 40（`Input`／`DatePicker`／`SegmentedControl` 不要再縮成 `h-9`、`size="sm"`，並排時會差幾 px），區塊標題 `text-base font-semibold`。
- **會被側滑面板擠窄的區塊**用 container query 依自己的寬度排（例如看診工作區 `@container/visit`），不要照視窗寬度排。
- 兩個工作台（診療台、掛號台）用 `xl:h-[calc(100dvh-2.5rem)]` 撐滿高度，裡面各自捲動。

### 清單頁模板

照兩個工作台卡片的骨架：

```
PageHeader（標題＋主要動作，例如「新增貓咪」）
DataCard title="貓咪清單" :count
  #filters  → 卡片標頭右邊：SegmentedControl／FilterBar（搜尋膠囊）
  #tabs     → 標頭下方一條：FilterTabs（佇列，可帶計數）
  預設 slot → .desktop-data-header（44）＋ .desktop-data-row（64），1280px 以下改一筆一張小卡
  #footer   → ListFooter（「第 x–y 筆，共 n 筆」＋分頁）
```

- **篩選放在卡片標頭，不放頁首**——它篩的是這張卡片。頁首只留標題與主要動作。
- 列上只留一顆主要動作，其餘收進 `RowActions`（⋯ 選單）；某列沒有選單時用同尺寸的空位補齊，按鈕才對得齊。**列上唯一的主要動作一律 `soft`**（繼續填寫、查看報告、新增健檢、藥單的開啟、設定清單的編輯）——灰底的列動作看起來像沒作用；⋯ 選單維持 `secondary`。
- 載入中 `ListSkeleton inset`、空狀態 `EmptyState inset` 放在卡片裡面，不讓整張卡片消失。
- 用這個模板的：貓咪、健檢報告、寄送歷程、藥單、表單管理、文字模板。預填模板與初診表審核是左右兩欄（左清單可搜尋、右內容）。

### 資訊的排法

- **不用「·」「・」把多項資訊串成一行**（「米克斯 · 公 · 6 歲 · 回診」讀起來是一條雜訊）。
  - 標頭（看診工作區、櫃台處理視窗、病歷速覽、健檢報告資訊列、貓咪詳情、藥單詳情）用規格欄 `SpecGrid`＋`SpecCell`：小標題在上、值在下、欄間細線。
  - 空間小的地方（清單列、時間軸卡、暫存區）只寫「品種＋♂♀」（`PetLine`／`PetSex`）。
  - 其他短資訊靠**間距**分組（`flex gap-x-3`／`gap-x-4`），或寫成「標籤＋值」；標題裡的並列用「、」；句子裡用逗號或括號。
- 初診才出徽章，回診是預設、不另標。
- 表格裡不同屬性拆成不同欄（品種、性別分開）。
- **沒有值就留白**：不補「未填…」「尚無…」「待確認」「—」，格子照畫、內容空著（需要時 `min-h-lh` 撐一行）。畫面只寫事實，不替資料下結論、不加說明句。例外：整個清單是空的空狀態、載入／錯誤訊息、修改前後對照裡的「（空白）」、下拉選項本身的「未記錄」。

## 6. 元件

| 需求 | 用什麼 | 注意 |
|---|---|---|
| 按鈕 | `<Button variant>`：`default` 實色、`secondary` 下凹底＋細邊、`soft` 主色淡面＋細邊、`destructive` 淡紅底＋細邊、`destructive-solid` 實心紅 | **靜止時一定有底色**（沒有透明的 `ghost`）；淺色的 `secondary`／`soft`／`destructive` 帶一圈同色系細邊，淡面放在白卡片上邊緣才不會糊掉。**推進流程的動作用 `soft`**（繼續填寫、新增健檢、審核、報到、處理、安排回診、開啟健檢報告、藥單的開啟、套用、送 IDEXX…）；取消、返回、關閉、分頁、重試、取回、就地編輯的鉛筆鈕、圖示鈕、日期前後鈕、⋯ 選單這類輔助動作用 `secondary`。實色 `default` 只給那一區唯一的主要動作。實心紅只給確認視窗裡的最終動作（刪除、捨棄、取消掛號／藥單、標記未到；`ConfirmDialog` 加 `destructive`），沒有例外——遲到靠卡片紅底與徽章表示，不靠紅色按鈕 |
| 頁首 | `PageHeader` | 每頁第一個子元素；詳情／編輯頁用 `back-to`，不用麵包屑 |
| 清單主卡片 | `DataCard`＋`ListFooter` | 見第 5 節「清單頁模板」 |
| 卡片 | `<Card>` | 自帶邊框、底色、陰影，使用端不要再加 |
| 對話框 | `<DialogContent size>`＋`DialogHeader`／`DialogFooter`；簡單的用 `ModalDialog` | 只有一種標頭與頁尾；不要覆寫寬度。`2xl`（最寬 90rem）只給櫃台處理視窗 |
| 側滑面板 | `panels/SidePanel.vue`（標頭：返回／標題／動作／關閉） | 開在工具欄旁，不遮擋背景 |
| 下拉選單 | `ui/dropdown-menu`；清單列的次要操作用 `RowActions` | 危險項放最後、前面一條線、靜止就是紅字 |
| 滑過提示 | `v-tip="文字"`（`lib/tooltipDirective.js`）；截斷文字用 `v-tip.overflow`（真的截斷才出）；需要排版的（總覽長條圖）用 `ui/tooltip` | **不用原生 `title`**：要停很久才出現、樣式不一致。只有圖示的按鈕沒有 `aria-label` 時，指令會用提示文字補上 |
| 貓咪名／飼主名 | `<PatientLink :pet-id>`（飼主、有底色的警示列加 `quiet`） | 一律連到貓咪詳情頁，飼主名也是（飼主沒有自己的頁面）。名字在按鈕／選項裡、初診還沒建檔、報告頁、貓咪詳情頁自己不用 |
| 頁籤／分段 | `FilterTabs`（可帶計數）、`SegmentedControl` | 兩者外觀相同（`segment-track`／`segment-active`）。側滑面板這種窄的地方用 `FilterTabs fit`：平分一列、不橫向捲動，每格上面數字、下面短標籤（item 給 `short`） |
| 規格欄 | `SpecGrid`＋`SpecCell label` | 身分資訊一律用它 |
| 貓咪一行 | `PetLine`（品種＋♂♀）、`PetSex` | |
| 提醒標籤 | `ReminderTags`（過敏／病史／注意，`lib/petDisplay.js` 的 `petReminders`） | 完整內容在滑過提示，列高不變 |
| 去處標記 | `DestTag to="journal|report|internal|medication"` | 診療台欄位旁：寫完會去哪裡 |
| 號碼牌 | `CheckinNumber size` | 候診灰、看診中主色實心、待櫃台淡面、已完成淡灰。掛號台時間軸卡片最左邊那顆圓：報到後是號碼牌，還沒有號碼是貓圖示 |
| 手術／遲到 | `SurgeryBadge`、`LatenessBadge` | 紫與紅，刻意分開色相；並排時順序「手術 → 遲到」 |
| 保證金 | `DepositBadge`（`:status` 掛號上的「已收保證金 200」／`:required` 貓咪上的「約診需收保證金 200」）、`DepositField`（約診時的二選一） | `warning` 琥珀：是要櫃台處理的錢，不是警示，跟紅色遲到徽章靠色相分開。「這次不收」的掛號不畫徽章。`DepositField` 只在這隻貓達到門檻時出現，掛號視窗與約回診共用；沿用（綠底）與「○○ 繳過保證金」（藍底）只說明、不必選 |
| 做決定的二選一 | `OptionButtons`（`v-model`、`:options`） | 選中的整顆主色實心＋打勾，沒選的卡片底＋細邊，一開始可以都沒選。切換檢視才用 `SegmentedControl`——它的選取項只浮起一塊卡片底，放在有色底的區塊上太淡 |
| 出席 | `AttendanceBadges`（貓咪詳情頁頁首）、`AttendanceSummaryTable`（掛號視窗）、`AttendancePanel`（出席紀錄頁籤） | 頁首徽章「遲到 N 次｜最近 9/28」：`danger` 淡面膠囊、中間一條細線、0 次不畫，點了切到出席紀錄頁籤；只標貓咪、只算這隻貓。掛號視窗的對照表是淡紅底表格，一列貓咪、一列「飼主○○名下」，三欄遲到／未到／最近一次——掛號當下要知道這家人會不會遲到；0 的格子留白、沒有紀錄的對象不列 |
| 格式文字 | 編輯 `RichTextEditor`（待辦 `single-line`＋`toolbar-position="top"`；健檢報告的多行文字用 `formfields/RichTextField`，文字模板鈕在工具列右邊）、顯示 `RichText`（報告紙面 `palette="report"`；清單摘要 `one-line`） | 不用 `v-html`。清單上的摘要也畫出顏色與粗體 |
| 空狀態／載入 | `EmptyState`、`ListSkeleton` | 不要只寫「載入中…」 |

## 7. 用語

員工畫面：貓咪、飼主、櫃台、醫師、健檢報告、健檢表單。「藥單」是物件，「領藥」只指交付那一步。寄送結果叫「已寄出」（不是「寄送成功」——郵件伺服器收下不等於送達）。公開初診頁（飼主看的）維持「貓孩兒／家長」。

## 8. 報告紙面

`/report/:token` 與 `/records/:id/preview` 是 PDF 的來源，**固定淺色、A4 尺度**，改動要格外小心：

- 用 `report-*` token，不跟主題切換；在那兩頁加東西不要借用後台的樣式常數。
- 紙面裡共用的元件（牙齒圖）讀的是後台 token，所以 `style.css` 淺色區塊的選擇器是 `:root, .report-sheet`——紙面內一律拿到淺色值。這類元件的行內樣式寫原始 token（`var(--field)`），不要寫 `var(--color-field)`：後者在 `:root` 就算定值，擋不住 `html.dark`。
- `.report-sheet` 把字級（12／14／16／20／24px）與行高（1.5）鎖住。後台的字級、行高怎麼改都不影響紙面；反過來，動到 `.report-sheet` 或報告元件就要重新比對分頁。
- 比對方法：用假資料（完整填寫、典型內容兩種）把改動前後各印一次 A4 PDF，比頁數與逐像素畫面，明暗主題都要跑。
- 多行文字的顏色走 `report-danger`／`report-warning`／`report-success`／`report-info`。

## 9. 各畫面的定案細節

通用規則之外，幾個工作畫面的排法與理由。

### 診療台「今日病患」（左欄）

- **時間軸樣式**：時間欄右邊一條貫穿整份清單的軌道，每列一顆圓點表示階段（看診中主色實心＋光圈、候診主色空心、未報到灰虛線、遲到未報到紅虛線、候診太久紅框、交出琥珀、完成綠）；「進行中」照預約時間插「現在」虛線（今天、門診時間內）與午休分隔（上下午都有人才畫），跟掛號台時間軸同一套。
- **「進行中」是一條清單**：不分組、不能收合，在院、手術、還沒報到全部照預約時間排；手術整列 `bg-surgery-surface/70`（選中那列的淡主色底優先）。目前這筆只用淡主色底標出，列上沒有關閉鈕。
- **每一列長得一樣**：左邊一律是預約時間（`num`；有號碼牌的底下一行小字「3 號」，精簡版有沒有號碼都同高），名字旁「初診」（`info`）與「手術」，右邊一顆狀態徽章——只畫圖示＋數字，文字在滑過提示與 `aria-label`（候診主色淡面沙漏＋分鐘、看診中主色實心聽診器＋分鐘、交出琥珀箭頭＋時刻、完成綠勾＋時刻，候診滿 20 分改紅）。精簡版一行要放名字、標籤、來院原因、狀態與按鈕，用圖示每顆省約 30px。
- **還沒報到的不畫徽章**：在「看診」鈕的位置放一個按鈕外觀（`secondary`）、`w-20` 的「未報到」，過了寬限換成 `destructive` 樣式的「遲 N 分」（全文在滑過提示）——每一列右邊都有一顆同尺寸的東西。它不是按鈕（`span`），點下去跟點整列一樣。時鐘圖示保留給「報到時遲到」。
- 還在院內的列另標檢驗進度：已送 IDEXX 還沒有結果是 `info`「檢驗中」、這次看診已有結果是 `success`「檢驗已出」（詳細版是徽章、精簡版是燒瓶圖示）——驗血要十幾分鐘，醫師多半已經切去看別隻。

### 診療台看診工作區

- 一次一筆，標頭沒有關閉鈕；點左欄哪一列就換成哪隻貓，切換前先存檔（同時掛好幾筆時看不出開了哪幾筆）。
- **檢驗報告**（`VisitLabTable`，在本次簡易紀錄正上方）：顯示這隻貓當天的 **IDEXX 原始結果**，不是健檢報告上的數值——醫師要看儀器給的全部項目，不受表單有沒有對應欄位影響。`bg-sunken` 唯讀區塊，一台儀器一段（小標「生化 Catalyst One 10:36」），寬的時候兩欄（`@2xl/visit`），每列「代號｜數值｜參考範圍＋單位」，偏高偏低 `text-danger` 帶 ↑↓，段落最後是 IDEXX 的原文註記，標題旁 `danger` 徽章「異常 n 項」；限高 `max-h-80` 可捲動（一次檢驗常有二三十項）；沒有去處標記（它是參考資料）。
- 標題右邊「匯入檢驗結果」（`soft` `sm`）開 `LabImportDialog`：搜尋框（IDEXX 上的貓名／飼主）＋一列一份還沒確認是哪隻貓的結果，**不限當天**（儀器＋時間，不是今天的連日期一起寫；`info`「同名」、`success`「今天」、`danger`「異常 n 項」），同名的排最前，其餘新到舊 50 筆；列上一顆「匯入」，匯入後提示帶「復原」、視窗留著。
- 標題旁的**填入狀態燈號**（`LabFillStatus`）：`secondary` `sm` 按鈕，裡面一顆 10px 圓點＋一句摘要（「已填入 12 項」「2 項跟報告不同」），點開 `Popover` 看每台儀器的明細。綠＝有填入、黃＝有數值差異／沒選健檢表單／報告已結案、藍＝沒有填入新數值，沒有結果不畫。**表單沒有對應欄位不算黃燈**——全血檢二十幾項、表單只列幾項是常態。健檢報告填寫頁「引用本次看診」那一條也有同一顆。
- **底部操作列**：送 IDEXX（`soft`，燒瓶圖示）、開啟健檢報告、取消看診、完成看診送交櫃台（或取回修改、申請修改），全部 40 高。送出 IDEXX 後換成徽章＋`secondary`「取消送 IDEXX」：抓檔程式回報寫進主機之前是 `warning`「尚未送到 IDEXX」，之後才是 `info`「已送 IDEXX 14:05」——抓檔程式離線時通知只是排著隊，按了不等於主機上看得到。掛號台在院卡片的 ⋯ 選單第一項是同一個動作，卡片名字旁出同一組徽章。

### IDEXX 數值比對視窗

`LabConflictDialog`（`ModalDialog size="md"`），像 Windows 覆蓋檔案的比對：表格一列一項「勾選框｜項目｜報告上目前 → IDEXX」，數字 `num`，勾選的列 `bg-accent`、舊值劃掉；項目下面一行小字是參考範圍與單位，兩邊的值偏高偏低紅字帶 ↑↓。**預設全部不勾**（醫師手打的可能是刻意修正的）。底部左「都不要」`secondary`、右「全部覆蓋」`secondary`＋「覆蓋勾選的（n）」`soft`——有顏色的是要先勾才按得下去的那顆，不是一按就全部換掉的。✕＝稍後再說。按下去之後的提示帶「復原」。

### 「檢驗」面板

- 待確認清單照初診面板的版型：上方搜尋框（IDEXX 上的貓名／飼主名；IDEXX 主機補傳歷史紀錄時清單可能有幾百筆），有建議人選（同名且當天唯一）的列右邊一顆 `soft` `sm`「確認是○○」直接確認，點列本身是推入確認畫面（候選是當天掛號的單選卡片，同名加 `info` 小標、唯一同名預選；數值表格偏高偏低 `danger` 箭頭；底部左「忽略」`secondary`＋確認對話框、右「確認是○○並填入」`soft`）。忽略後的提示帶「復原」——忽略之後它不在任何清單上。
- 另有「數值跟報告不同」段落，開同一個比對視窗。
- **標頭的抓檔程式燈號**（關閉鈕左邊）：每台診所電腦一顆 12px 圓點，`success`／`warning`／`danger` 實色＝綠／黃／紅，外面留 36px 感應範圍，滑過用 `v-tip` 顯示狀態與最後回報時間；紅燈可以點、確認後移除那筆紀錄（換電腦留下的舊紀錄）。離線時工具欄徽章顯示「!」（沒有待確認結果也亮）；從沒裝過就不顯示。平常只佔一點位置，要看才展開——開發者不在診所，抓檔程式停了要有人看得到。

### 掛號台

- 卡片左邊是貓（最左一顆圓：號碼牌或貓圖示；名字、初診徽章、手術／遲到徽章、來院原因、請轉告飼主、飼主備註），右邊對齊的三欄：飼主／電話（附複製鈕）／進度（只有狀態與時間，沒有小標題），最右是主要動作＋`RowActions`。卡片底色只在還沒報到時用遲到（紅）／手術（紫）。
- **掛號視窗**（`AppointmentDialog`）是置中的雙欄 Modal：左欄誰、為什麼，右欄時段格（`SlotGrid`，15 分鐘一格、格內列已約的名字）。選了貓之後下面出現出席對照表與保證金欄位。
- **櫃台處理視窗**（`HandoffSheet`，`size="2xl"`）：標頭一排（號碼牌｜貓、徽章、來院原因｜飼主規格欄＋預約、交櫃台、完成時間），飼主備註整條攤開在標頭下。左欄「跟飼主說」照講話順序編號：①請轉告飼主（有內容才用警示底，空的灰底——空的橘框像有事要講）②本次簡易紀錄（上面一排體重、體溫，下面「上傳影像」勾選框），歷次病歷日誌直接展開在下面；右欄 ③約回診：醫師建議在上（標籤與內容同一行），`AppointmentSlotPicker split` 讓日期、診療時間、來院原因、手術一窄欄、時段格在旁邊——大部分就診都會當場約回診，時段一打開就要看得到。底部左邊一句結果（「完成後會約 10/12（週一）14:30 回診」），右邊完成處理／退回處理中／核准修改。90rem 是右欄還能並排的下限。
- 搜尋是跨日的：有關鍵字時時間軸換成搜尋結果表（清單列樣式、不限日期、新到舊、分頁），點一列回到那一天、把卡片捲進畫面並框起來——電話裡問「我約哪一天」時不知道日期。

### 其他

- **待辦**：完成是勾選框（`ui/checkbox`，面板 28px、總覽 24px——20px 難點），勾起來內文槓掉，取消勾選＝改回未完成。星號鈕（置頂）是 `secondary` 底、標上後星星填 `warning` 色，只有未完成的列有；星號是標記不是流程動作，所以不用 `soft`。待辦輸入框的格式工具列放上方（單行輸入框塞不下）。
- **總覽**：近 8 週健檢量是 CSS 長條（單一序列，只標最新一週），滑過整欄出 `Tooltip`（日期範圍＋份數；0 份那週也有 2px、整欄都滑得到）。
- **聊天面板**標頭有「通知」鈕（自動通知開關），設定選單也有同一個入口——只放在設定選單裡找不到。
- **藥單**：`/medications` 是清單頁模板（DataCard 分欄、一顆主要動作＋⋯），點貓咪整頁切到詳情；已確認的藥單是唯讀檢視、藥單內容放大（拿藥包逐項對照）。全頁版與工具欄面板（`compact`）是同一個 `MedicationWorkspace`，功能一致，依裝置身分決定預設頁籤與可用動作。
- **貓咪詳情頁**的遲到／未到：頁首徽章＋獨立的「出席紀錄」頁籤；只標貓咪這邊、只算這隻貓（不記「誰帶來的」，貓咪與飼主各標一組只是同一件事的兩個數字）。

## 10. 公開初診頁（`/intake`，飼主填的）

飼主在診所現場、用自己的手機填，所以版面以手機為準，跟後台是兩套東西：

- **不跟主題切換**，色值是 `style.css` 的 `--intake-*`（跟 `report-*` 一樣獨立）。強調色只有一個 `--intake-accent`（Logo 的暖色系，白字對比 5:1），按鈕、勾選、聚焦、小標題都用它；不要借後台的 `primary`。這一頁借用了 `ui/input`、勾選框、單選鈕，它們讀的是 `bg-field`／`border-input`，所以 `style.css` 讓 `.intake-page` 跟 `.report-sheet` 一樣再宣告一次淺色 token——少了它，深色模式下驗證碼欄位與勾選圓點會變成黑底。
- **字級 16px 為底**：輸入框小於 16px 時 iOS Safari 一聚焦就放大整頁。提示與錯誤訊息 14px。
- **點擊範圍 44px**：選項是整塊可點的膠囊（`option-label`，選中淡暖底）、輸入框與年月選單有外框。電腦版同一套外觀，只在 640px 以下改單欄、貼齊螢幕、送出鈕滿寬。
- **品種是下拉選單＋打字篩選**（`BreedSelect appearance="intake"`）：必填、只能從清單選；選項一列 44px、16px 字（清單傳送到 body 底下，所以樣式寫成 `style.css` 裡有前綴的全域 class `intake-combobox-*`）。欄位下方固定一行「不確定品種請選米克斯或其他」。
- **花色是同一個外觀的「建議＋自由輸入」**（`IntakeSuggestInput`，reka-ui Autocomplete）：點開列出常見花色，打字篩選，清單上沒有的照打照存。**規則跟品種相反：打的字就是值，建議要明確挑才算**——清單剛出來不反白任何一項，直接按 Enter 只收起清單、保留自己打的字；用方向鍵移過去或點選才換成建議。不要用原生 `<datalist>`：清單由瀏覽器自己畫，外觀跟品種下拉差很多，手機上也常常不出現。
- **生日**：必填的「出生日期」用原生日期欄（手機上是系統的日期滾輪；後台的 `DatePicker` 日曆傳送到 body 底下、會跟著深色主題）＋永遠顯示的「不知道生日？用概略年齡推算」（歲、個月、「套用」），套用＝回推成那個月 1 日、標題改「預估生日」、送 `birthDateEstimated: true`；選了日期就取消推估標記。日期下面的小框即時顯示換算出的年齡。填了年齡卻沒按套用就送出時，送出那一刻自動套用。
- **除了市話，每一欄都必填**，每一格標紅星號、出錯在那一格下方說明。選了「有」的那一項連帶補充欄必填（主餐勾「其他」要寫內容、已注射與有健檢要選年份、有過敏要寫藥物、定食定量要寫餐數）；家中貓口 1–99。規則在 `shared/intakeRequired.js`（`intakePetIssues`），後端用同一份擋，改規則只改那裡。
- **病史第一個選項是「無」**，跟其他病史互斥（`toggleMedicalHistory`；櫃台審核修改同一套），存成 `medicalHistory: ['無']`。**「無」不是病史**——醫療警示、病歷速覽、清單提醒一律經過 `lib/petDisplay.js` 的 `medicalHistoryText`／`petReminders` 濾掉，不要直接 `medicalHistory.join()`。
- **補充欄跟選項綁在一起**：在「已注射／有」後面的欄位打字就自動選「有」，改選「無」就清空（`linkDetail`）。
- **數字欄用 `inputmode="numeric"` 的文字欄，不用 `type="number"`**：打字當下擋掉超過上限的那一鍵（`blockOutOfRange`）；number 欄位讀不到游標、還會收 `e`、小數點與負號。數字打錯立刻提示；「沒填」與 Email、手機格式等送出才提示，送出鈕上方另有「還有 N 個欄位」摘要。
- **草稿**存 `sessionStorage`（重新整理還在、關掉分頁就沒了、送出後清掉），驗證碼一起存、重新整理自動再驗；**不顯示任何提示**——接回來的資料對飼主來說就是「本來就還在」。
- 用語維持「貓孩兒／家長」。

## 11. 畫面修改的流程

1. **大改**（新頁面、版面重排、新元件類型）：先做設計提案（claude.ai 設計稿或 artifact 頁面），使用者確認後才實作。
2. **小改**（間距、文案、既有元件的細節）：直接改程式。
3. **改完同一次**：
   - 更新本文件對應段落，規則有變就把理由一起寫下（「為什麼不這樣做」往往比「怎麼做」更有用）；寫的是現行規則，不是修改過程。
   - 新增或改動元件用法時，更新第 6 節的表。
   - 會影響「最容易做錯」的規則時，同步 CLAUDE.md 第七節。
   - 驗證：`npm run build`（含色碼檢查）、`npm test`、`npm run test:workflow-browser`、`npm run test:medication-browser`；動到報告就照第 8 節比對紙面。
