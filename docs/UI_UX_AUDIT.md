# UI／UX 健檢與改善追蹤

最後更新：2026-09-03

這份文件把原本只存在對話中的健檢結論落到專案內。狀態以目前程式碼與實際桌機／手機畫面為準。

## 已完成

| 面向 | 改善結果 |
| --- | --- |
| 資訊架構 | 側邊導覽、頁面標題、主要操作與返回路徑已有一致規則；列表狀態同步到網址。 |
| 視覺系統 | 後台使用語意色彩、統一字級、按鈕層級、圓角與卡片間距，並支援明暗主題。 |
| 色票治理 | 一般 UI、固定淺色報告、圖表／牙位圖分層管理；頁面不再散落固定 Tailwind 色階或 HEX，建置前會自動執行色彩稽核。 |
| 操作語意 | 編輯統一為中性 `secondary`；刪除入口統一為紅色 `destructive`，最終刪除確認使用實心紅色。 |
| 桌機版面 | 標題與主要操作共用 `PageHeader`；篩選與搜尋依可用寬度排列，不再各自占滿一列。 |
| 表格密度 | 六個桌機清單使用 44px 表頭、56px 單行資料列；長內容省略、無補空白列，1280px 無水平溢位。 |
| 響應式 | 1280px 以下改用手機卡片；候診時間軸在 390px 重新分配時間、身分與操作區，不擠壓成不可讀窄欄。 |
| 載入回饋 | 清單使用與正式資料列同高的骨架，降低載入完成時的版面跳動。 |
| 錯誤恢復 | 工作台與候診頁載入失敗會提供重新載入；工作台不再因空資料繼續渲染而拋出頁面錯誤。 |
| 背景更新 | 候診頁每分鐘靜默更新，保留現有內容，不再整頁閃回載入骨架。 |
| 操作安全 | 刪除報告為真正刪除；取消掛號可記錄原因，取消與標記未到診都有確認視窗，誤按後可恢復至候診流程。 |
| 掛號維護 | 尚未報到的掛號可編輯身分快照、聯絡方式、時段與來院原因；已取消／未到掛號可從同頁恢復。 |
| 觸控與無障礙 | 搜尋輸入區擴充為完整膠囊高度；主要頁面沒有無名稱按鈕或未標示輸入欄位，390px／1280px 皆無頁面水平溢位。 |

## 後續驗收

以下不屬於已知程式缺陷，但上線前仍應完成：

1. 使用診所真實長文字與每日實際資料量，走一次「掛號 → 報到 → 完成看診 → 建立報告 → 結案與寄送」。
2. 由實際操作者確認候診時間軸的資訊順序與用詞是否符合現場習慣。
3. 正式部署前加入認證與寄信頻率限制；這是安全性必要項目，詳見 `CLAUDE.md` 的待辦。

## 驗證基準

- 桌機：1280 × 900。
- 手機：390 × 844。
- 清單表頭／資料列：44px／56px。
- 不允許頁面水平溢位、無名稱純圖示按鈕或未標示的輸入欄位。
- 前端改動需通過 `npm run build` 與 `npm test`。
