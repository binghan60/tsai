# 診務協作

正式入口：醫師 `/appointments`、櫃台 `/reception`、獨立看診 `/appointments/:id/visit`。

兩個工作台共用每日預約與即時更新，分別記住時間軸／候診表格偏好。日期、篩選、搜尋與選取項目保留於網址；由看診頁返回時恢復列表位置。時間軸按預約時段，表格將候診者依報到時間優先排列。

工作台只保留一組含數量的狀態篩選。時間軸分為可收合的上午／下午時段，顯示時間節點與現在位置。櫃台每列直接提供報到、未到、收款與約回診等適用操作；點整列開啟側邊就診詳情，分為收款明細、交接事項與回診安排，關閉後焦點回到原列。醫師點列則進入獨立看診頁。

## 工作責任

- 醫師：診療量測、簡易紀錄、處方與批價、櫃台交辦、飼主提醒、回診建議。
- 櫃台：新增／修改預約、報到、未到、取消／恢復、收款、交辦完成標記、安排回診。
- 醫師簡易紀錄與寵物病歷日誌為同一筆資料，修改或清空會同步；兩份資料一起交易提交。
- 正式表單按需建立。一次就診連結一份草稿，重複開啟沿用原紀錄，儲存後可返回看診頁。收款不會建立報告。

## 三個獨立完成標記

`billingCompletedAt`、`visitCompletedAt`、`paymentCompletedAt` 各自代表批價完成、看診完成及收款完成。可以先批價收款，再完成看診，也可以先完成看診再批價。

原 `status` 保留作為既有儀表板的摘要：兩項看診與收款皆完成才成為 `completed`；已批價為 `pending_checkout`；其餘已報到為 `arrived`。所有新介面應透過 `shared/appointmentWorkflow.js` 判斷細部狀態。

沒有 `workflowVersion: 1` 的舊資料以原狀態推導完成標記，第一次新版操作才保存標記。舊完成紀錄不會重新收款。進入新版的紀錄拒絕舊版頁面送出的完成／退回／診療編輯請求。

## 同步與收款

新版命令使用 `/api/appointments/:id/workflow/:action`，需附 `version`（文件 `__v`）。過期請求回傳 409，不會覆寫最新資料。收款另外核對 `billingRevision`；撤回與重新批價都會改變批價版本。收款後費用鎖定，實收與批價不同時需填調整原因。補收／退款仍需另行處理，本版不提供修改已收款交易的功能。

Socket.IO 推播狀態與資料，另有 30 秒重新載入及重連補載。正在輸入的欄位不被無關更新覆蓋；同欄位發生衝突時顯示最新內容，交由使用者選擇。正式提交期間暫停編輯，避免送出期間輸入被回應覆蓋。

回診預約與本次就診在同一交易中建立關聯，重複操作沿用關聯預約。若原回診已被報到或取消，不會自動覆寫。需 MongoDB replica set，與既有報到、報告交易的要求相同。

## 驗證

在 `server` 執行 `npm test`、`npm run lint`；在 `client` 執行 `npm test`、`npm run build`。

`client` 的 `npm run test:workflow-browser` 啟動獨立記憶體資料及本機 Vite／Socket.IO，使用現有 server Puppeteer 套件實測兩個工作台。涵蓋切換、導頁、自動儲存、同步衝突、即時批價收款、獨立完成標記、檢視偏好及手機寬度。不連診所 MongoDB，也不寄送訊息或報告。

正式 MongoDB 交易與實際帳務仍需在測試資料庫驗收；記憶體 API／瀏覽器測試不能代替 replica set 整合測試。
